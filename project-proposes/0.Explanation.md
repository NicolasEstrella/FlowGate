# Project Proposes

Esta pasta contem uma sequencia ordenada de propostas de trabalho para o projeto FlowGate.

Os arquivos foram derivados da documentacao em `docs/01-overview.md`, `docs/02-architecture.md`, `docs/03-workflow-engine.md`, `docs/04-features.md` e `docs/05-use-cases.md`.

O objetivo desta pasta e quebrar a visao macro do produto em propostas menores, independentes e aplicaveis por repositorio, mantendo uma ordem de execucao que reduz bloqueios entre front, back e infra.

## Como usar

1. Aplique os arquivos na ordem numerica.
2. Cada proposta aponta claramente o repositorio alvo.
3. Um mesmo repositorio aparece mais de uma vez porque a evolucao foi fatiada por fase.
4. Cada arquivo pode ser usado como base para um propose de OpenSpec ou como briefing de implementacao.
5. As dependencias listadas em cada arquivo indicam o que precisa existir antes da execucao.

## Ordem definida

1. `1.FlowGate_Infra_Foundation_propose.md`
   Base local da plataforma com servicos essenciais e ambiente de desenvolvimento integrado.
2. `2.FlowGate_Core_Foundation_propose.md`
   Fundacao do backend com dominio, persistencia, auditoria e contratos iniciais.
3. `3.FlowGate_Portal_Foundation_propose.md`
   Casca inicial do portal Angular com navegacao, autenticacao e integracao base.
4. `4.FlowGate_Core_Workflow_Engine_propose.md`
   Implementacao do motor de workflow, regras, state machine e endpoints de execucao.
5. `5.FlowGate_Portal_Requests_Approvals_propose.md`
   Fluxos de solicitacao, inbox de aprovacoes, timeline e acoes do usuario.
6. `6.FlowGate_Core_Async_Automation_propose.md`
   Mensageria, workers, notificacoes, documentos, SLA e escalonamento.
7. `7.FlowGate_Portal_Admin_Operations_propose.md`
   Area administrativa e operacional com visibilidade de workflows, auditoria e SLA.
8. `8.FlowGate_Infra_Hardening_Delivery_propose.md`
   Endurecimento da infraestrutura, observabilidade e preparo para ambientes alem do local.

## Principios usados na divisao

- Infra primeiro para disponibilizar dependencias reais do sistema.
- Backend estrutural antes das features centrais do engine.
- Portal base antes das telas operacionais.
- Automacoes assincronas depois que o fluxo sincrono estiver funcional.
- Camada administrativa e endurecimento de infra ao final, quando o comportamento principal ja estiver estavel.

## Resultado esperado

Ao concluir todos os proposes desta pasta, o projeto deve convergir para a visao descrita nos docs: uma plataforma de workflow empresarial com portal web, API orientada a dominio, motor de workflow configuravel, processamento assincrono, auditoria, SLA e infraestrutura conteinerizada.
