# Proposal 4 - FlowGate Core Workflow Engine

## Repositorio alvo

FlowGate.Core

## Objetivo

Implementar o coracao do produto: o motor de workflow com state machine, avaliacao de regras, orquestracao de etapas e API para submissao e decisao de solicitacoes.

## Base documental

- `docs/02-architecture.md`
- `docs/03-workflow-engine.md`
- `docs/04-features.md`
- `docs/05-use-cases.md`

## Escopo

- Implementar fluxo de criacao, submissao, aprovacao, rejeicao, ajuste e cancelamento de solicitacoes.
- Criar state machine coerente com os estados descritos na documentacao.
- Implementar avaliacao inicial de regras dinamicas por tipo de processo, valor e contexto da solicitacao.
- Suportar execucao sequencial, condicional e paralela das etapas principais.
- Modelar atribuicao de aprovadores e deadlines por etapa.
- Expor endpoints para iniciar workflow, listar pendencias, aprovar, rejeitar, solicitar ajuste e consultar historico.
- Registrar trilha de auditoria em cada transicao relevante.
- Cobrir ao menos os cenarios de reembolso simples, reembolso acima de 5 mil, reembolso acima de 10 mil, contrato paralelo e loop de ajuste.

## Entregas esperadas

- Workflow engine funcional dentro do backend.
- Rule engine inicial orientado a configuracao ou estrategia extensivel.
- State machine persistida e auditavel.
- API pronta para o portal operar o ciclo principal do negocio.

## Criterios de aceite

- Os cenarios de uso descritos nos docs conseguem ser executados fim a fim de forma sincrona.
- Cada transicao valida atualiza estado, responsavel, prazo e auditoria corretamente.
- Fluxos sequenciais e paralelos convivem no mesmo modelo.
- O pedido de ajuste reinicia o fluxo de forma controlada.
- O backend passa a refletir o comportamento central prometido pelo projeto.

Implementar em `FlowGate.Core` o workflow engine principal do FlowGate com state machine, rule engine inicial, suporte a etapas sequenciais, condicionais e paralelas, endpoints para submissao e decisao de solicitacoes, deadlines por etapa e trilha de auditoria. A implementacao deve cobrir os cenarios dos docs, especialmente reembolso, contrato paralelo e ajuste de solicitacao.
